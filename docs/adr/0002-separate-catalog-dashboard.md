# Separate web dashboard for catalog maintenance

The founder needs the full text-catalog maintenance workflow without routine YAML edits and publication commands. Use a separate, laptop-first web dashboard hosted on Cloudflare and restricted to the founder rather than administrative screens in the iOS training app, because catalog editing benefits from a larger screen and the editor can evolve independently of iOS releases. Edit, review, and publish during one visit without saved drafts or autosave. Cloudflare Access restricts entry to the founder's exact email using email-code login and sessions configured for up to one month on the Free plan; privileged server requests must verify that authorization. Technical design must automate consistency with repository content.

Use Astro with TypeScript, server-rendered pages, native HTML forms and Astro Actions, plain CSS, and small browser scripts where editing interactions need them. Deploy with the official Cloudflare adapter to a dedicated Worker from `admin/` in the existing repository, reusing the catalog publisher and Neon records. This interface is primarily form-based content maintenance, so a single-page application and its client framework would add complexity without a current requirement. See [the accepted stack](../system-design.md#accepted-dashboard-stack).
