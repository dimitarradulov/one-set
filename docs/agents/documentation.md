# Documentation conventions

- Use relative Markdown links and two-space indentation for nested lists.
- Name new prose files with lowercase, hyphenated names.
- Do not create `*-plan.md` files unless the user explicitly asks for one. Put approved behavior in requirements, implementation proposals in the relevant design document, and implementation work in GitHub Issues.
- For product and design documents, follow the [sources of truth](project-context.md).
- Review links and code examples in changed documents.
- Document required configuration variables with placeholders only. Use `.env.example` for committed environment examples.
